2.2 Config 配置类

class Config:
    data_dir: str = "./data"      # 数据集下载目录
    output_dir: str = "./output"  # 输出文件目录
    model_name: str = "efficientnet_b0"
    pretrained: bool = True
    fine_tune_mode: str = "full"  # "full" 或 "freeze"
    batch_size: int = 16
    num_epochs: int = 30
    lr: float = 1e-4              # 学习率
    weight_decay: float = 1e-4    # L2 正则化
    num_workers: int = 2           # 数据加载子进程数
    seed: int = 42
    device: str = "cuda" if torch.cuda.is_available() else "cpu"

为什么要用类集中管理参数？

  1. 改参数不用翻代码：所有可调参数在一个地方，一目了然
  2. 对比实验方便：想试试 lr=1e-5 的效果？只改这一个数字
  3. 换网络只需改一行：model_name = "resnet50" 就换了

每个参数的含义：

参数 作用 为什么是这个值
batch_size=16 每次喂给 GPU 的图片数量 Y7000P 的 8GB 显存跑 16 比较安全，设 32 可能爆显存
num_epochs=30 把全部训练数据反复学多少遍 对于小数据集，30 轮通常足够收敛
lr=1e-4 参数更新的步长 迁移学习的标准起点，比从头训练(1e-3)小一个数量级
weight_decay=1e-4 L2 正则化强度 防止权重过大导致过拟合
seed=42 随机种子 任何数字都行，42 是深度学习界的"梗"（《银河系漫游指南》）
device 自动选 GPU 还是 CPU torch.cuda.is_available() 检测是否有 NVIDIA 显卡

2.3 set_seed：固定随机种子

def set_seed(seed: int = 42):
    random.seed(seed)          # Python 内置 random 库
    np.random.seed(seed)       # NumPy 随机数
    torch.manual_seed(seed)    # PyTorch CPU 随机数
    torch.cuda.manual_seed_all(seed)  # PyTorch GPU 随机数
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False

为什么需要固定随机种子？

深度学习里到处都是随机：权重初始化是随机的、数据增强是随机的、数据打乱是随机的……如果你不固定种子，每次训练的结果都不一样。那问题来了：你改了网络结构发现准确率提高了 2%，到底是结构改进带来的，还是这次"运气好"随机到了好的初始化？

固定种子 = 排除"运气"这个变量，让实验结果变得可复现。

cudnn.deterministic = True 让 GPU 使用确定性算法（代价是稍慢），benchmark = False 关闭自动算法搜索。两者配合才能保证每次运行完全一致。

2.4 阶段一：数据准备

2.4.1 build_transforms() — 数据预处理流水线

def build_transforms():

这个函数返回两套变换：一套给训练集，一套给验证/测试集。区别在于训练集有数据增强，验证集没有。

训练集变换：

train_transform = transforms.Compose([
    transforms.RandomResizedCrop(224, scale=(0.7, 1.0)),
    transforms.RandomHorizontalFlip(p=0.5),
    transforms.RandomRotation(degrees=20),
    transforms.ColorJitter(brightness=0.3, contrast=0.3, saturation=0.3, hue=0.1),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
])

transforms.Compose([...]) 把多个操作串成一条流水线，图片依次经过每一项。

步骤 做了什么 为什么需要
RandomResizedCrop(224, scale=(0.7,1.0)) 随机裁剪一个区域，缩放到 224×224 模拟花朵在画面中位置/大小不同。scale=(0.7,1.0) 表示裁出来的区域占原图 70%~100%
RandomHorizontalFlip(p=0.5) 50% 概率左右翻转 花朝左和朝右应该是同一种花，模型不该依赖朝向
RandomRotation(degrees=20) 随机旋转 ±20° 照片不一定正着拍，斜一点模型也得认识
ColorJitter(...) 随机微调亮度/对比度/饱和度/色相 模拟不同光照、天气、相机参数
ToTensor() (H, W, C) 变成 (C, H, W)，像素值 0-255 变为浮点数 0-1 PyTorch 要求的输入格式
Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]) 每个通道减均值除标准差 这些数字是 ImageNet 数据集上统计出来的。预训练模型在 ImageNet 上训练时用的就是这个标准化，换了别的数字，预训练权重会"水土不服"

验证集变换（不做增强）：

eval_transform = transforms.Compose([
    transforms.Resize(256),      # 直接缩放到 256
    transforms.CenterCrop(224),  # 从正中间裁 224×224
    transforms.ToTensor(),
    transforms.Normalize(...),   # 标准化必须和训练集一致
])

验证/测试集为什么不做数据增强？ 因为你需要公平地评估模型。如果把测试图也随机翻转旋转，那每次评估的结果都不一样，没法判断模型到底好不好。验证集的预处理是确定性的——同一张图每次进来的结果完全一样。

2.4.3 build_dataloaders() — 构建数据加载器

def build_dataloaders(train_set, val_set, test_set, cfg):

train_loader = DataLoader(
    train_set,
    batch_size=cfg.batch_size,  # 每批 16 张图
    shuffle=True,               # 打乱顺序
    num_workers=cfg.num_workers,# 2 个子进程并行加载
    pin_memory=(cfg.device == "cuda"),  # GPU 时锁页内存加速
)

DataLoader 的三个核心参数：

  • batch_size：一次同时处理多少张图。16 意味着模型一次前向传播会看到 16 张不同的图，然后对这 16 张图的 loss 取平均再反向传播。batch 越大，梯度估计越稳定，但显存占用也越大。
  • shuffle=True：每个 epoch 重新洗牌。防止模型记住数据的顺序（比如先看 10 张玫瑰再看 10 张百合）。
  • num_workers=2：用 2 个子进程并行从硬盘读图片。如果设为 0，数据加载和 GPU 计算会串行进行，GPU 经常"等数据"，训练变慢。但 Windows 上不建议设太大（多进程在 Windows 上有坑）。

2.5 阶段二：模型搭建

2.5.1 build_model() — 创建模型

def build_model(num_classes: int, cfg: Config):

核心就一行：

model = timm.create_model(
    cfg.model_name,          # "efficientnet_b0"
    pretrained=cfg.pretrained,  # True → 自动下载 ImageNet 权重
    num_classes=num_classes,    # 102 → 自动替换最后的 FC 层
)

timm.create_model 在背后悄悄做了两件事：

  1. 下载预训练权重：从 HuggingFace（或镜像）下载 efficientnet_b0 在 ImageNet 上训练的权重文件（约 20MB）。这些权重包含了模型在 100 万张图上学到的"怎么看边缘/纹理/形状"的能力。

  2. 替换分类头：原模型最后一层是 Linear(1280, 1000)（对应 ImageNet 的 1000 类）。timm 检测到 num_classes=102，自动改为 Linear(1280, 102)。这 102 个新神经元的权重是随机初始化的，所以分类头部分需要从零学起。

2.5.2 两种微调策略的实现

这是整个实验中最重要的设计选择。

"freeze" 模式 — 冻结特征提取层：

if cfg.fine_tune_mode == "freeze":
    for name, param in model.named_parameters():
        if "classifier" in name or "head" in name or "fc" in name:
            param.requires_grad = True   # 分类头 → 可训练
        else:
            param.requires_grad = False  # backbone → 冻结

requires_grad = False 告诉 PyTorch："这个参数不需要计算梯度"。梯度 = 0 意味着 optimizer.step() 不会更新它。所以只有分类头的那几千个参数会被训练，backbone 的几百万个参数纹丝不动。

"full" 模式 — 全部参数训练：

else:  # "full"
    # 什么都不做，所有参数默认 requires_grad=True

两种方式怎么选？

场景 推荐
数据集很小（每类 < 50 张）、和 ImageNet 类似 freeze
数据集较大、或目标域和 ImageNet 差异大（如医学影像） full
追求最高性能 full（但需要更多正则化手段防过拟合）
快速验证想法 freeze（快得多）

本项目用 full，因为 Flowers 102 仍是自然图像，全微调能让 backbone 也适应花卉的纹理特征。

2.5.3 build_loss_optimizer() — 损失函数和优化器

criterion = nn.CrossEntropyLoss()

CrossEntropyLoss 内部做了什么？

  1. 模型输出 102 维向量（叫 logits），比如 [2.1, -0.5, 1.3, ...]
  2. Softmax 把 logits 变成概率：[0.45, 0.03, 0.18, ...]（和为 1）
  3. 取真实类别对应的那个概率 P_true
  4. Loss = -log(P_true)

如果概率是 0.9 → loss = 0.105（小，说明模型很确定） 如果概率是 0.1 → loss = 2.30（大，说明模型搞错了）

CrossEntropyLoss 其实 = Softmax + NLL Loss 的合并。PyTorch 把两步合成一步是为了数值稳定性。

optimizer = optim.AdamW(
    model.parameters(),
    lr=cfg.lr,              # 1e-4
    weight_decay=cfg.weight_decay,  # 1e-4
)

AdamW vs 普通 SGD：

  • SGD：所有参数用同一个学习率，容易在某些方向震荡
  • Adam：每个参数有自己独立的学习率（根据历史梯度自动调整），收敛更快更稳
  • AdamW：修正了 Adam 的权重衰减实现（L2 正则化从 loss 中分离出来），是目前最常用的优化器
scheduler = optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=cfg.num_epochs,   # 30 个 epoch 完成一个余弦周期
    eta_min=cfg.lr * 0.01,  # 最低降到初始 lr 的 1%
)

学习率调度在做什么？

学习率的变化曲线是一个余弦波的前半段：

lr │ 1e-4 ┤╲ │ ╲ │ ╲ │ ╲ │ 1e-6 ╲________ └─────────────────────→ epoch

训练早期 lr 大 → 快速收敛到最优区域附近。训练后期 lr 小 → 精细调整，不跳过最优点。这比固定学习率效果好。

2.6 阶段三：训练循环

这是整个深度学习最核心的部分。理解了这个循环，你就理解了"模型到底是怎么学习的"。

2.6.1 train_one_epoch() — 单轮训练

def train_one_epoch(model, dataloader, criterion, optimizer, device):

model.train()  # 切换到训练模式

model.train() 做了什么？ - 启用 Dropout：训练时随机丢弃一部分神经元（防过拟合），评估时不丢 - 启用 BatchNorm 的统计更新：训练时用当前 batch 的均值/方差并更新移动平均，评估时用训练好的移动平均

忘记写 model.train() 会导致 Dropout 不工作、BatchNorm 统计量错误，模型可能根本不收敛。

训练循环的核心五步：

for images, labels in pbar:      # 每次取 batch_size=16 张图

    # 步骤 1：清零梯度
    optimizer.zero_grad()

    # 步骤 2：前向传播
    outputs = model(images)      # 16 张图 → 16×102 的预测分数

    # 步骤 3：计算损失
    loss = criterion(outputs, labels)  # 标量，如 1.245

    # 步骤 4：反向传播
    loss.backward()              # 计算每个参数对 loss 的偏导数

    # 步骤 5：更新参数
    optimizer.step()             # 沿梯度反方向微调所有参数

这五步到底在干什么？用一个日常例子理解：

你在玩飞镖。你蒙着眼，身边有个人告诉你"偏左了 5 厘米，偏高了 3 厘米"。

步骤 代码 飞镖类比
① zero_grad 清零梯度 忘掉上一轮的"偏左偏右"信息
② forward model(images) 投出一镖，看落到哪里
③ loss criterion(outputs, labels) 量一下距离靶心多远
④ backward loss.backward() 计算"我应该往哪个方向调、调多少"（梯度）
⑤ step optimizer.step() 调整手的位置（更新参数）

重复几千次，你就能越投越准。

关键细节：为什么 optimizer.zero_grad() 必须在第一步？

PyTorch 的梯度默认是累加的。如果你不先清零，这一轮的梯度会和上一轮的加在一起，导致参数更新方向错误。PyTorch 设计成累加是为了方便某些需要累积梯度的场景（如大 batch 模拟），但 99% 的情况下你需要先清零。

_, preds = torch.max(outputs, 1)

torch.max(outputs, 1) 返回两个东西：最大值（那个分数）和最大值的位置（第几类）。我们用 _ 扔掉分数，只用位置作为预测结果。

running_loss += loss.item() * images.size(0)

loss.item() 把只有一个元素的 PyTorch tensor 取出来变成一个普通的 Python float。乘以 images.size(0)（这个 batch 的图片数）是因为之后要算加权平均——不同 batch 大小可能不一样（最后一个 batch 通常不满 16 张）。

2.6.2 evaluate() — 验证/测试

@torch.no_grad()
def evaluate(model, dataloader, criterion, device):

model.eval()  # 切换到评估模式

model.eval() 做了什么？ - Dropout 关闭（所有神经元都参与计算） - BatchNorm 使用训练时累积的移动平均，而不是当前 batch 的统计量

@torch.no_grad() 装饰器的作用：告诉 PyTorch 在这个函数里不要构建计算图。不构建计算图就省了大量显存和计算——验证时你不需要反向传播，所以梯度信息毫无意义。

for images, labels in dataloader:
    outputs = model(images)   # 只有前向传播
    loss = criterion(outputs, labels)
    # 没有 zero_grad / backward / step！

验证循环只有两步：前向传播 → 算 loss。没有反向传播，没有参数更新。验证集只是"测验"，不做"学习"。

2.7 阶段四：评价指标与可视化

2.7.1 get_all_predictions() — 收集所有预测

@torch.no_grad()
def get_all_predictions(model, dataloader, device):
    model.eval()
    all_labels = []
    all_preds = []
    for images, labels in dataloader:
        outputs = model(images)
        _, preds = torch.max(outputs, 1)
        all_labels.extend(labels.cpu().tolist())  # 真实标签
        all_preds.extend(preds.cpu().tolist())    # 预测标签
    return np.array(all_labels), np.array(all_preds)

这个函数的作用：把整个数据集跑一遍，收集所有样本的真实标签（图片实际是什么花）和预测标签（模型认为是什么花）。这两个数组是计算混淆矩阵和所有指标的原材料。

2.7.2 compute_metrics() — 计算四大指标

def compute_metrics(y_true, y_pred, num_classes: int):
    acc       = accuracy_score(y_true, y_pred)
    precision = precision_score(y_true, y_pred, average="macro")
    recall    = recall_score(y_true, y_pred, average="macro")
    f1        = f1_score(y_true, y_pred, average="macro")
    cm        = confusion_matrix(y_true, y_pred)

四个指标一句话解释：

想象你是安检员，要从 102 种花里找出"玫瑰"：

预测=玫瑰 预测≠玫瑰
真实=玫瑰 TP（猜对） FN（漏了）
真实≠玫瑰 FP（误报） TN（猜对）
  • Accuracy = (TP+TN) / 总数 → "总共对了多少"
  • Precision = TP / (TP+FP) → "你说'是玫瑰'时，多少真的是玫瑰"
  • Recall = TP / (TP+FN) → "所有真玫瑰，你找到了多少"
  • F1 = 2×P×R/(P+R) → "P 和 R 加权平均，两者都高 F1 才高"

为什么用 average="macro"？

宏平均 = 对 102 类各自算 Precision，然后取平均（每类权重相同）。与之相对的是 "micro"（微平均 = 把所有类混在一起算）。对于类别不平衡的数据集（比如测试集中某些花有 200 张图，某些只有 40 张），macro 更能反映模型对小类的表现。

2.7.3 plot_loss_acc_curves() — 绘制 Loss/Acc 曲线

fig, axes = plt.subplots(1, 2, figsize=(14, 5))

# 左图：Loss
axes[0].plot(epochs, history["train_loss"], "b-o", label="Train Loss")
axes[0].plot(epochs, history["val_loss"], "r-s", label="Val Loss")

# 右图：Accuracy

怎么读这两张图： - 训练 Loss 持续下降 → 模型在学习 - 两条 Loss 都降 → 模型泛化良好 - 训练 Loss 降但验证 Loss 升 → 过拟合！模型在背训练集答案，遇到新图就傻眼 - Acc 趋于平稳 → 接近收敛，继续训练意义不大

2.7.4 plot_confusion_matrix() — 绘制混淆矩阵

这个函数生成两张图：

计数版（Blues 配色）：

im = ax.imshow(cm, cmap="Blues", aspect="auto")

每个格子里的数字 = 真实类别 i 被预测为类别 j 的图片张数。对角线上的数字越大越好（猜对了）。

归一化版（YlOrRd 配色）：

cm_norm = cm.astype("float32") / row_sums  # 每行除以该行总和
im = ax.imshow(cm_norm, cmap="YlOrRd", aspect="auto", vmin=0, vmax=1)

每个值 = 该行所有样本中被预测为 j 的比例（所以值在 0-1 之间）。对角线接近 1.0（黄色）= 几乎全猜对。非对角线有亮块 = 容易混淆的类别对。

为什么要做两个版本？ 计数版告诉你"哪两类之间混淆最多张"，归一化版告诉你"某类的样本中有多少比例被误判了"。102 类的混淆矩阵太大，归一化版用颜色区分更直观。

2.7.5 analyze_confusion() — 找出最易混淆类别

cm_no_diag = cm.copy().astype(float)
for i in range(num_classes):
    cm_no_diag[i, i] = 0  # 对角线清零，只看误分类

# 遍历所有 (i,j) 对，找混淆次数最多的

3. inference.py 逐段解析

inference.py 是独立推理脚本。它不参与训练，只做一件事：加载已训练的模型，对一张新图片进行分类。

3.1 load_model() — 加载模型

model = timm.create_model(
    "efficientnet_b0",
    pretrained=False,        # 注意！这里不需要预训练权重
    num_classes=num_classes,
)
checkpoint = torch.load(model_path, map_location=device)

推理时 pretrained=False 但 load_state_dict 加载我们自己的权重。这两个操作不矛盾： - pretrained=False：不下载 ImageNet 权重（省时间，反正会被覆盖） - load_state_dict(...)：把我们训练好的权重（包含微调后的所有参数）加载进来

注意 map_location=device：如果模型是在 GPU 上训练的但你用 CPU 推理，这个参数会自动处理设备映射。

3.2 preprocess_image() — 预处理输入图片

image = Image.open(image_path).convert("RGB")

transform = transforms.Compose([
    transforms.Resize(256),
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225]),
])

tensor = transform(image).unsqueeze(0)  # (3,224,224) → (1,3,224,224)

.unsqueeze(0) 是干嘛的？ 模型期望输入维度是 (batch_size, channels, height, width)。单张图是 (3, 224, 224)，少了一维。unsqueeze(0) 在第 0 个位置插入一个维度，变成 (1, 3, 224, 224)（batch_size=1）。

预处理必须和训练时的 eval_transform 完全一致。如果你训练时用了 Resize(256)+CenterCrop(224) 但推理时用了 Resize(224)，图片的像素分布就变了，模型会"水土不服"。

3.3 predict() — 推理

@torch.no_grad()
def predict(model, input_tensor, device="cpu"):
    outputs = model(input_tensor)                    # (1, 102)
    probabilities = torch.nn.functional.softmax(outputs, dim=1)
    top_prob, top_class = torch.max(probabilities, dim=1)
    return top_class.item(), top_prob.item()

Softmax 的作用：把 102 维的 logits 向量变成概率分布（所有值在 0-1 之间，加起来等于 1）。

例如：[1.2, 0.8, -0.3, ...] → [0.35, 0.23, 0.08, ...]

每个值代表"这张图属于该类别的概率"。取最大概率的类别作为预测结果。

3.4 Top-5 预测

top5_prob, top5_class = torch.topk(probs, k=5, dim=1)

除了第一名，还打印前 5 名。如果第一名和第五名的概率差距很大（如 0.85 vs 0.02），说明模型很确定。如果前几名概率都差不多（如 0.35 vs 0.30 vs 0.25），说明模型比较犹豫——这张图可能正好在类别之间的模糊地带。

5. 核心概念深度讲解

5.1 反向传播：模型到底怎么"学习"？

这是深度学习中最重要的概念。用一个具体的例子：

假设模型输入一张玫瑰的图，输出 102 维的分数：

真实标签：class_0（假设这是玫瑰）
模型输出：[2.1, -0.5, 1.3, ..., 4.2, ...]  ← 102 个分数

CrossEntropyLoss 计算：
1. Softmax → [0.08, 0.01, 0.05, ..., 0.45, ...]  ← 102 个概率
2. 取 class_0 的概率 = 0.08
3. Loss = -log(0.08) = 2.53  ← 很大！说明模型很没把握

反向传播的本质：loss.backward() 计算"如果我把某个参数稍微调大一点，loss 会怎么变化"（偏导数）。对于上亿个参数，这个计算是用链式法则自动完成的。

优化器的本质：optimizer.step() 沿每个参数的负梯度方向微调。梯度为正（参数增大→loss增大）→ 减小参数。梯度为负（参数增大→loss减小）→ 增大参数。

经过几千次这样的微调，模型的输出慢慢变成：

模型输出：[5.8, -1.2, 0.3, ..., 0.1, ...]  ← class_0 的分数最高
Softmax  → [0.92, 0.01, 0.02, ..., 0.001, ...]
Loss     = -log(0.92) = 0.08  ← 很小！模型很有把握猜对

5.2 迁移学习 vs 从头训练

从头训练 迁移学习（本项目）
初始权重 随机 ImageNet 预训练
需要的数据量 百万级 几十到几千
训练时间 数天到数周 数十分钟到数小时
底层特征 需要从头学边缘/纹理 已经会了，只需微调
适用场景 拥有海量数据和计算资源 资源有限（教学、研究）

迁移学习可行的原因：图像的底层特征是通用的。不管是识别猫还是识别花，第一步都是"找到边缘、分辨颜色、识别纹理"。这些能力在 ImageNet 上已经训练好了，所以可以复用。

5.3 过拟合：深度学习最常见的坑

过拟合 = 模型在训练集上表现完美，但遇到新图片就翻车。

怎么判断过拟合？看 loss_acc_curve.png：

  • 训练 Loss 一直降，验证 Loss 却开始上升 → 过拟合
  • 训练 Acc 接近 100%，验证 Acc 却卡住不动 → 过拟合

本项目的防过拟合手段：

手段 代码位置 原理
数据增强 build_transforms() 让模型每次看到不同的"变体"，防止背答案
L2 正则化 weight_decay=1e-4 惩罚过大的权重值，迫使模型"走中庸路线"
Dropout EfficientNet 自带 训练时随机禁用部分神经元，防止过度依赖特定路径
验证集监控 每个 epoch 算 val_acc 发现验证指标恶化就停（本项目没做 early stopping，但保留了接口）

5.4 batch_size 对训练的影响

batch_size 优点 缺点
小（8-16） 显存友好、梯度噪声有助于跳出局部最优 训练不稳定、速度较慢
大（64-256） 梯度估计准确、GPU 利用率高 显存需求大、可能收敛到尖锐的局部最优

本项目用 16 是在 Y7000P 8GB 显存限制下的安全选择。

6. 常见问题 FAQ

Q1：跑 train.py 时报 "ConnectionError: huggingface.co"

答：代码已经设置了 HF_ENDPOINT 镜像。如果镜像也挂了，手动下载 efficientnet_b0 的 .pth 文件放到 ~/.cache/torch/hub/checkpoints/ 目录下即可。

Q2：跑 train.py 时报 "CUDA out of memory"

答：把 Config.batch_size 从 16 改成 8 或 4。

Q3：我想换 ResNet-50 试试

答：把 Config 里的 model_name 从 "efficientnet_b0" 改为 "resnet50"。代码其他部分完全不用改——这就是用 timm 而不是直接写死网络结构的好处。

Q4：怎么知道自己有没有过拟合？

答：看 output/loss_acc_curve.png。如果训练 Loss 一直降但验证 Loss 反过来上升，就是过拟合了。可以尝试：减小学习率、增加 weight_decay、增加数据增强、或者改用 freeze 模式。

Q5：inference.py 用的图片不是花怎么办？

答：模型只有 102 个花的类别，输入一张猫的照片它也只会输出"最像某种花"。这是分类模型的局限——它不知道"我不知道"。实际应用中需要额外的"不确定"检测机制。

Q6：为什么代码里有些 import 放在函数外面，有些放在里面？

答：Python 惯例是全部放顶部。但 import json 放在了 main() 函数内部（第 919 行），这是个小瑕疵——应该移到顶部。不过它不影响运行，只是风格问题。

Q7：我想把训练好的模型部署到手机上

答：需要把 .pth 文件转为移动端格式（如 ONNX → Core ML 或 TFLite）。EfficientNet 本身是移动端友好的架构，适合部署。

最后复习：这个实验的完整流程用一句话概括

"用 ImageNet 上预训练的 EfficientNet-B0，把最后 1000 类分类头换成 102 类花卉分类头，在 Oxford Flowers 102 数据集上全参数微调 30 轮，最终在 6149 张测试图上达到了约 86% 的分类准确率。"
